The pipeline

Every upload lands on one screen. The Upload & Run button reconciles everything in one go, and the Reconciliation menu is where you check the result and produce the workbook you submit.

Anything the engine can't decide on its own waits in Mismatch Review for a person to look at, and any change an Auditor proposes there waits again in Match Approvals for sign-off. Dashboard gives an at-a-glance check of where things stand at any point, without opening a single tab.

The five steps

  1. 1 Confirm Master Data Bank accounts, divisions, locations
  2. 2 Upload & Run One drop zone, one button
  3. 3 Review the results Dashboard & Reconciliation Results
  4. 4 Handle mismatches Mismatch Review & Match Approvals
  5. 5 Download the report Audit Working Report → Client Report
Golden rule: load all the source documents for a period before you trust any number. A receipt shows as Unmatched simply because the bank statement that would clear it has not been uploaded yet.

Step 1 — Confirm Master Data

Open Master Data › Division & Bank A/C. It maps each hospital bank account number to one of Hitech City Somajiguda Secunderabad Malakpet — locations kept in Master Data › Location Master Admin only, so add a location there first if a new one is opening. Division & Bank A/C itself is pre-loaded; add a row whenever an account opens or closes, then re-run reconciliation for any affected bank statement. The division drives the report's LOCATION and NAME OF THE AUDITOR columns, and the same list is what the Location filter on Mismatch Review offers.

Step 2 — Upload & Run

Every source — MIS, bank, gateway settlement, cheque, refund — drops into the same screen: Reconciliation › Upload & Run. One .xlsx / .xls file, or several at once, up to 70 MB each. The system reads each file's own content to work out what it is, so file names don't matter. A file already ingested is rejected outright, and duplicate rows inside a new file are skipped — so it is always safe to re-send a corrected file.

Auto-detection and the pre-upload check

Drop a file and it is identified from its content, not its name — the matching type is pre-ticked automatically (a combined workbook can genuinely contain more than one report, and each gets stored under its own type). A file the system doesn't recognise asks you to pick a type by hand. An MIS/HIS file also gets a dry-run preview first: a per-sheet check against the report's own printed totals, a flag for rows already stored in another batch, and anything held back for a human look, with a reason for each. Files with warnings need an explicit "I have reviewed the warnings — include this file" tick before the run will include them.

Run Reconciliation — one button, everything at once

Files are staged, not saved, until you press it — nothing is uploaded or matched a moment before that. Skip batches already generated is off by default, so a run redoes every pipeline; tick it to leave already-generated batches alone and only process what's new — much faster on a repeat run.

Redoing just one pipeline

Most of the time Run Reconciliation is all you need. To redo a single pipeline on its own — after uploading just a corrected CARD MPR, say — use its own tab instead:

Each unit tab becomes its own batch, tagged with the unit name read from row 1 of the sheet. If that name has no recognisable division, the rows cannot be division-scoped — check the export's first row.

Step 3 — Review the results

Two places to check the numbers: Dashboard for a fast glance, Reconciliation › Reconciliation Results for the full detail behind them. Both read the same saved verdicts, so they never disagree.

Dashboard

The screen every signed-in user lands on. Five headline tiles — Reconciled (% and progress), Needs Attention, Awaiting Approval, Collection Value and Bank Data Up To — each click through to the screen behind it. Below that, a Reconciliation Flow lane per collection type (Online, Cheque, Card, UPI) shows MIS uploaded → bank/MPR uploaded → reconciled % → items to review, plus status charts and a Bank & Gateway Files table. Admins also see the last few Shared Folder Check runs here.

Step 4 — Handle mismatches

Anything the engine couldn't decide on its own, and anything anyone wants to double-check, goes through two screens: Mismatch Review to look at it, Match Approvals to sign off a change to it.

Mismatch Review

Reconciliation › Mismatch Review — one tab per collection type (Online (IP + Diag/OP), Cheque, Card, UPI), and four views inside each tab:

ViewShows
AllEvery transaction, matched or not
Mismatches defaultEverything short of a clean match
MatchedClean system matches — browsable, so a wrong one can still be caught
Matched by AuditorJust the ones an auditor locked by hand

Filter by Search (patient, receipt or reference), Location (an Auditor only ever sees their own assigned branches), Department and From date. Show up to defaults to Till last bank upload — each branch is cut off at its own latest bank statement date — or pick As on date for a fixed cut-off. Click any row to open the full record with the plain-English reason it didn't tally.

Admin actions apply straight away — Mark as Matched, Reset to Unmatched. An Auditor instead proposes a change — Propose as Matched, Propose a Correction — which sits in Match Approvals until their Reporting Manager signs off. An auditor-approved match is final; it can't be re-opened from here. On the Mismatches view, select several rows to propose them as Matched together with one shared reason.

Match Approvals

Reconciliation › Match Approvals — the checker's side of that same flow, for whoever the Auditor reports to. Two tabs: To Review (requests from people who report to you) and My Requests (your own, with their Pending / Approved / Rejected status). Open a request to Approve or Reject it (a note is required to reject, optional to approve), or select several for Approve Selected / Reject Selected.

Approving a Correction unlocks the record and resets it to Unmatched — the next reconciliation run re-decides it from scratch.

Step 5 — Produce the Audit Working Report final output

Open Reconciliation › Reconciliation Results, Audit Working Report tab.

  1. Pick the period — Daily, Monthly, Yearly or a Date range. Monthly + 2026-07 gives the label JUL-26, used in the file name and every sheet title.
  2. Choose the date it filters on — Receipt Date (normal) or Realization Date (only receipts whose bank credit cleared in the period).
  3. Narrow to one location if needed — the Unit dropdown defaults to All Units.
  4. Read the preview — confirm totals and that Unmatched is as low as you expect.
  5. Download Client Report — saves as Audit Working Report - JUL-26.xlsx. This is the deliverable.

How matching works

Most receipts match straight to a bank line. Three exceptions work differently.

Two-stage matching

Two streams reconcile in two hops rather than one.

Card & UPI Reconciliation — a direct match, its own module

Card and UPI receipts are reconciled by a separate module from the one behind IP/Diag Payment Rules above, in a single hop: the MIS row is tied straight to the gateway's own settlement line — by approval code for Card (CARD MPR or Pine Labs), by RRN for UPI (UPI MPR). A CREDIT/PAY refund pair — a failed UPI payment later returned to the payer — is excluded automatically. When several MIS rows share one settlement line, all of them show Grouped Matched.

Match statuses

  • Matched Reconciled 1:1 to a bank credit. The goal.
  • Grouped Matched Several MIS rows share one settlement line — Card / UPI Reconciliation and PayU / EaseBuzz Settlements.
  • EaseBuzz Matched Reconciled against a successful EaseBuzz gateway transaction.
  • Contra Entry Cheque collected then refunded — cancels out, matched to the refund document.
  • Partial Match Bank has the same reference with extra digits and the amount agrees. Fix the MIS reference, regenerate.
  • Amount Mismatch Reference matches a bank line but amounts differ beyond tolerance. Check both amounts.
  • Multiple Matches Found The reference matched more than one bank credit, so the engine stopped rather than guess — picking the wrong one would look settled. Choose the right one, or check whether the same settlement file has been uploaded twice.
  • Unmatched Nothing found. Read the Match reason — usually a missing upload or a data-entry slip.
  • No Gateway Row Nothing on the gateway or bank side to tie it to yet. Called No Bank Credit on PayU / EaseBuzz Settlements, No UPI MPR Row on UPI Reconciliation.
  • Pending Approval An Auditor's proposed change is waiting on their Reporting Manager in Match Approvals.
  • Excluded A rule removed the row from scope; it does not appear in the report.
  • Not generated This batch or pipeline has never been through Generate / Run Reconciliation.

Only on Unit Matches

Unit Matches reconciles a unit's combined total against one bank credit, so it adds two statuses the rest of the app doesn't use:

  • Partially Matched The unit's receipts add up to less than the bank credit — a short balance is still owed.
  • Amount Excess The unit's receipts add up to more than the bank credit — it over-collected.

Manage Rules

Reconciliation › Manage Rules tunes how the engine decides a match, as four tabs: IP Payment Matching, Diagnostics Payment Matching, Cheque Collection Matching and Gateway Matching — the last one covers PayU, EaseBuzz, CARD and UPI together, with a target picker inside to choose which gateway you're editing. Every "Manage Rules" link elsewhere in the app jumps straight to the right tab.

Editing a rule never rewrites a verdict that was already saved — it only changes what happens on the next run. Regenerate the affected pipeline (see "Redoing just one pipeline" under Upload & Run) to apply it.

Automation & Go-Live Admin only

Automation

Reconciliation › Automation has two tabs, in the order the day runs.

HIS Data Pull — every morning at the Pull Time (IST) the day before's IP, Diagnostics and OP collections are pulled straight from HIS for every unit and stored, so nobody has to press Sync. If HIS does not answer it tries again; a morning that was missed is caught up on a later one. Pull Now pulls a chosen day for every unit immediately — only what is not already pulled — and works while the daily pull is still switched off. Every pull is listed; open one to see each unit and day.

Shared Folder Check — checks one shared network folder on a schedule, pulls in anything new, and reconciles it — no manual upload. Configure a Shared Folder Path (a UNC path the server can read), a daily Check Time (IST), and a Batch "Uploaded By" Label so an auto-ingested batch is always visibly not a manual one, then toggle Automation Enabled and Save Settings. Run Now checks the folder immediately, without waiting for the scheduled time.

Every run is logged — Started / Trigger / Status / Found / Ingested / Skipped / Failed. Open a run for the per-file detail (Stored, Already stored, Not recognised, Needs a person, Nothing to store, Failed), each with a Retry option if nothing was stored from it.

A run that ingests anything — or finds collections pulled from HIS that are not yet reconciled — re-runs reconciliation automatically afterwards, the same as pressing Run Reconciliation by hand. Set the folder's Check Time after the HIS Pull Time.

Go-Live Settings

Reconciliation › Go-Live Settings holds one cutoff switch: a Go-Live Date and a Switch Enabled toggle. From that date, every clean match locks itself the moment it's generated, and MIS/bank records can no longer be deleted or edited. Turning the switch off pauses both effects — useful for pushing the date back — without touching the date itself.

If the picked date has already passed and the switch is on, locking and the delete freeze are in effect right now.

Master Data

Division & Bank A/C is covered in Step 1 above. Two more screens sit here, both Admin only.

Location Master

Master Data › Location Master is where a hospital location itself is added, renamed or retired — before it can be mapped in Division & Bank A/C, or picked as a branch/department filter anywhere else. "Delete" is really a soft deactivation: it stops the location being offered for new uploads or assignments, every record already tagged with it is untouched, and it can be restored any time.

User Management

Master Data › User Management is where accounts, roles and access live. Add User asks for an Employee ID, Full Name, a Temporary Password (the user must change it at first login), a Role, a Reporting Manager (who their proposed changes go to for approval in Match Approvals), which Branches an Auditor can see (Admins see every branch automatically) and which Screen Access they're granted (the Dashboard is always visible to everyone). Per-user actions cover Edit, Branches, Screen access, Reset password and Activity; an account locks itself after five failed logins and unlocks with one click. An Audit Log tab alongside the user list is a whole-application activity log — who did what, and when, searchable and filterable.

Troubleshooting

SymptomCause & fix
"All rows already present" / upload rejectedThe file or its rows are already loaded. To reload, delete the old batch first.
Many Unmatched receiptsThe bank statement / PayU MPR for that date range or account is not uploaded, or its batch was never generated. Check the Summary banners.
Partial MatchMIS reference is truncated. Fix it on the MIS row, regenerate.
LOCATION blank or wrong in the reportBank account not in Division & Bank A/C, the location isn't in Location Master yet, or the MIS unit name has no division. Fix Step 1, regenerate.
Report shows no rowsWrong period format (Monthly needs YYYY-MM), nothing uploaded, filtering on Realization Date before anything cleared, or a Unit filter with no matching data.
Refunded cheque shows UnmatchedThe refund document for that period is not uploaded. Upload it, regenerate the cheque batch.
Card / UPI row shows No Gateway RowCARD MPR, Pine Labs, or UPI MPR for that period isn't uploaded yet, or Card / UPI Reconciliation hasn't been generated. Upload it, press Generate on that tab.
Pending Approval never clearsCheck Match Approvals › To Review. Nothing shows there unless the requester's Reporting Manager is set correctly in User Management.
Can't delete an MIS row or a batchThe Go-Live date has passed and the switch is on — deletes are frozen from that date. Check Go-Live Settings.
A file dropped in the shared folder never shows upAutomation isn't enabled, today's check time hasn't run yet, or the path is wrong. Open Automation › Shared Folder Check and use Run Now to check immediately.
"Rules have changed" bannerPress Regenerate on that tab, or re-run everything from Upload & Run.
