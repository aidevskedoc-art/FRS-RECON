The pipeline

Every upload screen loads one of three input families. The Reconciliation menu runs the match and produces the workbook you submit.

The five steps

  1. 1 Confirm Master Data Bank account → division mapping
  2. 2 Upload the sources MIS, bank, gateway, cheque, refunds
  3. 3 Generate On every batch + PayU Settlements
  4. 4 Review Reconciliation Summary for the period
  5. 5 Download the report Audit Working Report → Client Report
Golden rule: load all the source documents for a period before you trust any number. A receipt shows as Unmatched simply because the bank statement that would clear it has not been uploaded yet.

Step 1 — Confirm Master Data

Open Master Data › Division & Bank A/C. It maps each hospital bank account number to one of Hitech City Somajiguda Secunderabad Malakpet. It is pre-loaded. Add a row whenever an account opens or closes, then re-generate any affected bank statement. The division drives the report's LOCATION and NAME OF THE AUDITOR columns.

Step 2 — Upload the source records

All uploads take .xlsx / .xls up to 70 MB. A file already ingested is rejected, and duplicate rows inside a new file are skipped — so it is safe to re-send a corrected file.

Each unit tab becomes its own batch, tagged with the unit name read from row 1 of the sheet. If that name has no recognisable division, the rows cannot be division-scoped — check the export's first row.

Step 3 — Generate the matches

Uploading only loads raw rows. Generate runs the matching engine and saves a verdict onto every row. Nothing is matched until you press it.

Where to press Generate

  1. Each Bank Statement batch — Bank Statements → open → Generate.
  2. Each IP Payments and Diag OP Payments batch.
  3. Each Cheque Collection batch (IP and Diagnostics).
  4. PayU Settlements — Reconciliation › PayU Settlements → Generate.
Regenerate a batch when it shows the "matching rules have changed" banner, or after uploading a new bank statement / refund document that covers it.

Step 4 — Review

Open Reconciliation › Summary, set From / To to the period, press Apply. Clear every yellow "…never been through Generate" banner before you rely on the totals. Check the Amount Differences table at the bottom.

Step 5 — Produce the Audit Working Report final output

Open Reconciliation › Audit Working Report.

  1. Pick the period — Monthly + 2026-07 gives the label JUL-26, used in the file name and every sheet title.
  2. Choose the date it filters on — Receipt Date (normal) or Realization Date (only receipts whose bank credit cleared in the period).
  3. Read the preview — confirm totals and that Unmatched is as low as you expect.
  4. Download Client Report — saves as Audit Working Report - JUL-26.xlsx. This is the deliverable.

Two-stage matching

Two streams reconcile in two hops rather than one.

Match statuses

  • Matched Reconciled 1:1 to a bank credit. The goal.
  • EaseBuzz Matched Reconciled against a successful EaseBuzz gateway transaction.
  • Contra Entry Cheque collected then refunded — cancels out, matched to the refund document.
  • Partial Match Bank has the same reference with extra digits and the amount agrees. Fix the MIS reference, regenerate.
  • Amount Mismatch Reference matches a bank line but amounts differ beyond tolerance. Check both amounts.
  • Ambiguous More than one candidate; the engine will not guess.
  • Unmatched Nothing found. Read the Match reason — usually a missing upload or a data-entry slip.
  • Excluded A rule removed the row from scope; it does not appear in the report.
  • Not generated Generate has never been run on this batch.

Troubleshooting

SymptomCause & fix
"All rows already present" / upload rejectedThe file or its rows are already loaded. To reload, delete the old batch first.
Many Unmatched receiptsThe bank statement / PayU MPR for that date range or account is not uploaded, or its batch was never generated. Check the Summary banners.
Partial MatchMIS reference is truncated. Fix it on the MIS row, regenerate.
